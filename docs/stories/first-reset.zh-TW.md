# 從黃燈，到7%變100%

[回到專案首頁](../../README.zh-TW.md) · [English](first-reset.en.md)

最近做東西做得有點兇，常常打開Usage看還剩多少。後來乾脆把那個數字做成桌面小浮窗，再慢慢加上歷史紀錄和重置消息提醒。

9月12日，工具裡有一則黃色WATCH：團隊提過會偶爾重置，但沒有可靠時間。我看過後，小黃點繼續留著。那時我手上還有一張完整重置券，先忍住沒用。

![當天11%與黃色小點](../screenshots/field-case/01-watch-compact-11.png)

後來在FB Codex討論區，大家分享了更具體的消息，也幫忙換算時間。我就繼續用剩下的額度，順便留意。

一路剩到 **7%**，再看工具，變成 **100%**。

那張券也還在。老實說，真的有爽到。😂

![當天回到100%的原始截圖](../screenshots/field-case/03-quota-back-to-100.png)

*這張舊照片還有黃點。當時「補滿後舊提醒退場」還沒收好，後來才修正；我把原圖留下，不修掉它假裝一開始就完美。*

## 工具有幫上忙，但不是預言機

這次較具體的消息與時間資訊，來自社群。工具留下了WATCH和額度變化，**沒有證據說它及時抓到後續明確的INCOMING公告**，也不是它預測了幾點補满。

這則早期提示本來就已在網路流傳，不能說工具比我第一次看到社群消息還早。它的價值比較簡單：把值得留意的訊號放到桌面上，再留下本機紀錄。不用把它說得太神。

![當天的WATCH資訊與來源狀態](../screenshots/field-case/02-watch-details.png)

圖上67%代表6個設定來源中4個可正常讀取，並不是重置機率。訊號透過社群轉送來源取得，可回看原文；第三方來源也可能慢、漏掉，或與別站重複轉送。

## 本機留下的時間

以下是既有歷史經唯讀核對後的資料，時區為台灣時間UTC+8：

| 觀察 | 時間／值 |
| --- | --- |
| 補满前最後一筆採樣 | 2026-09-12 16:08:07，剩7% |
| 第一筆補满後採樣 | 2026-09-12 16:09:38，剩100% |
| 差異 | 增加93個百分點 |
| 完整重置券 | 前後都是1張 |
| 來源提供的下次重置日期 | 由9月15日移到9月19日 |
| 補額原因 | 未知；本機紀錄無法單獨證明全域原因 |

16:09:38是**本機第一次觀察到100%的時間**，不是伺服器精準执行時間。變化位於前後採樣區間內。早前口頭提到的15:11與留存紀錄不一致，這裡以本機紀錄為準，不宣傳「只差11分鐘」。

![當天歷史回升紀錄](../screenshots/field-case/04-history-replenishment.png)

原表格顯示15:54的7%是先前變化列；完整採樣中還有16:08:07的7%，所以能縮小觀察區間。
