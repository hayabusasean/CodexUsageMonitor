# 重置消息從哪裡來？有哪些限制？

[回首頁](../README.md) · [費用與資料安全](../PRIVACY.md) · [AI 使用指引](AI_HELP.md)

## 額度與消息是兩回事

自己的額度由電腦上的官方 Codex 回報；公開的重置消息由部分網站取得。**別人發文說要重置，不代表自己的帳號已補滿。** 工具把這兩種資訊分開保存。

## 程式設定的公開來源

以下是程式的來源清單，不代表每個網站現在都一定能讀取。網站也可能延遲、封鎖或改版。

| 網站 | 用途 | 網址 |
| --- | --- | --- |
| Codex 更新消息 | 官方公告 | https://developers.openai.com/codex/changelog/rss.xml |
| OpenAI 更新說明 | 官方公告 | https://openai.com/products/release-notes/ |
| OpenAI 服務狀態 | 官方服務狀態，作為背景參考 | https://status.openai.com/feed.rss |
| OpenAI 說明中心 | 官方重置券說明 | https://help.openai.com/en/articles/20001498-how-banked-codex-resets-work |
| ModelYard | 第三方轉送團隊公開貼文 | https://tibo.modelyard.dev/feed.xml |
| Codex Reset | 第三方轉送團隊公開貼文 | https://codex-reset.com/tibo |

不會自動登入私人 FB 社團或要求你的 X 登入資料。兩站轉送同一篇貼文，不算兩個獨立官方確認。網站拒絕讀取時，不應要求使用者交 Cookie 或關防護繞過。

## 提醒怎麼解讀

黃色提醒表示值得留意，紅色提醒表示讀到更明確的預告；兩者都不是帳號重置保證。收到重置券，也不等於額度已自動回滿。

金色標記表示本機觀察到額度回升。觀察時間不是官方精確執行時間；原因不確定就保留未知。曲線缺口表示沒有觀察到資料，不要自行補成連續用量。

來源可讀率只是納入計算的網站讀取狀態，不是全網涵蓋率、消息正確率或重置機率。

## 分享紀錄前

完整歷史與分析報告可能揭露使用習慣。回報問題先用版本、操作步驟及小份問題摘要；不要公開未檢查的私人紀錄。更完整的費用、本機資料與連線邊界見[費用與資料安全](../PRIVACY.md)。
